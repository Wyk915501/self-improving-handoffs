# self-improving-handoffs · 交接写时门 ＋ 协作教训

> English: [README.md](README.md) · 仓库：https://github.com/Wyk915501/self-improving-handoffs

**这是什么**：一套让"多个 AI 一起写交接报告"这件事**自己变好**的小系统。三层：

1. **写后检查**（零 LLM）：AI 每写完一份交接报告，脚本立刻查八项格式问题（G0–G7），把原因回给它，它自己改；写索引 README 时另查链接写法（G8，写时只报确定性两类）；每几小时的兜底扫描再查一遍，覆盖不经钩子的写入者。
2. **共用错题本**（每天一次、无人值守）：把别的 AI 挑出来的"协作机制类"错误自动归纳成一句话规矩，48 小时无人反对就生效。
3. **生效版分发**：只把当前生效的规矩（一行一条，正常 ≤15 条）生成一份短文件，配置了指针的宿主在**新开会话**时读到。**发布不等于使用**：只对加了指针的宿主生效；规则只在会话启动时载入，长会话不热更新；读没读、照没照做，程序都证明不了。

**解决什么问题**：规矩写在文档里没人在写的时候看；同类格式错误反复出现；每条新规矩都要人审批、循环转不起来。

**谁该用**：有两个以上 AI 工具（Claude Code／Codex／ZCode 之类）在同一棵 docs 树里互相交接的团队。单人单工具用不上。

**设计原则**（原项目负责人原话）："我需要一个更自动化的，即使任务能力缩小" / "只有它出了问题才需要我介入"。所以：能程序化的全程序化；模型只出候选、没有文件写权；人只做两件事——否决、和在某个窗口反复不过时去说一句。

**先说清验证范围**：这套东西只在原项目的一台 Windows 11 电脑（发布者）和一台 Linux 服务器（只装检查）上跑过一天多。Claude Code 的钩子两端都实测触发过；**ZCode 的钩子只验了配置能装、没实测它真的触发**；每日学习真实跑过一次（26 件进模型、程序拒收全部候选、新增 0 行）。它不是成熟产品，是一个可运行、有回归测试、边界写清楚的原型。

## 十分钟装起来

前提：Python 3.10+，`pip install pyyaml`（缺了脚本会 fail-closed 拦所有报告）；要跑每日学习还得有已登录的 `claude` CLI。

1. 把 `规范/交接写时门/` 整目录放进你的 docs 树（脚本用相对位置找同目录的提示词与测试，放哪都行）。
2. 把 `工作传递/交接模板.md` 放进你的 `docs/工作传递/`——写后检查从被查文件往上找这份模板取"必填键"清单；找不到就用内置清单。**这份模板有 38 个顶层键**，是原项目多 AI 循环用的全量版；G3 会要求你的每份报告都带齐。**先按你的需要删键**（保留 `status`、`report_id`、`frozen_at`、`observed_at`、`feedback_for`、`related_reports` 这几个脚本真用到的），不然写报告的成本会比你想象的高。
3. 先跑测试：`python 规范/交接写时门/tests/test_gate.py`（53 项全过再往下）。
4. 装写后检查 hook：按 `部署样例/` 里对应平台的片段，把 `<PYTHON>`、`<DOCS>` 换成你的路径。Claude Code 用户级＝这台机器所有项目生效；**共用 root 的服务器只装项目级**。
5. 验收不是看配置：故意写一份第一行不是 `---` 的 `*_交接报告.md`，看 AI 有没有当场收到"G1 frontmatter 不在第 1 行"。
6. 要错题本自动跑：改 `handoff_lessons.py` 顶部 `SOURCES`（哪些来源目录算"别的 AI 的判决件"），装计划任务／cron。**只能有一个发布者**（一台机器跑 collect/promote/publish），其他端只读生效版。
7. 规则文件加指针：Claude Code 在 `CLAUDE.md` 里 `@` 导入生效版；其他工具在它的规则文件里写一句"写报告前先读生效版"。

## 只需要人的两件事

- **否决**：在 `协作教训-否决记录.md` 加一行编号。48 小时内不否决＝同意；到期前 6 小时看门狗会再催一次（看门狗在跑才有，见下面"边界"的盲区条）；**错过了也能否决**，已生效的行进否决记录同样撤回，下次 publish 就从生效版消失——但已经把它读进上下文的进行中会话不会回收。
- **某个窗口反复不过**（一轮 ≥3 份）：弹窗会告诉你，去那个窗口说一句。

**弹窗与处理页的分工**（Windows）：弹窗不是做决定的地方——它只用一句话告诉你有这么回事、不管会怎样，给一个「去看看」；规矩全文、为什么会有这条、谁提的、什么时候生效，以及「同意／不采纳」两个按钮，都在处理状态页上。按钮走一个自定义 URL 协议（脚本自己注册，点一下就执行）。**弹窗里不要写内部编号和内部术语**，回归测试里有断言盯着——原项目负责人的原话是"我压根不知道 LG-06 是什么，这个提醒只会让我不知所措"。

其余都不需要人：候选由模型提名、程序核实——引文必须逐字见于原文；证据须来自 ≥2 个不同原始事件，且引用的原件必须在树里实存、且不在判决件来源目录里（只验存在，不验相关）；类别白名单；日增 ≤2、总量 ≤15。**命中权限／部署／同步／git／删除／密钥等关键词的候选不进表，但这只是自由文本之上的额外一层：换个说法就绕得过，反过来也会误拒合法教训**——真正的守门是前三条加否决窗。

## 边界，如实说

- 写后检查是"写后提示"，拦不住写入；只查格式，不查内容对不对。程序检查通过 ≠ 报告写得对。
- 只对**接了钩子的宿主**即时生效；Codex 之类不经钩子的靠每 N 小时的兜底扫描，且扫描清单只是近几小时的收件箱，不是长期待办。
- 链接检查（G6）只证明**本机**存在；两台机器 docs 树不完全一致时会有假断链，所以扫描模式忽略 G6 的断链项，只保留另一项 G6P"反斜杠链接"（另一台机器必断）。索引链接检查（G8）范围很窄：只报反斜杠、同目录裸文件名不存在、正斜杠目录前缀三类；含 `../`、绝对路径、http 的一律不报，不报不等于有效。
- 新规矩是自由文本，程序证明不了它"只关于报告写法"；判决件的叙述本身也不可验证——一份判决件引用任意真实存在的报告 ID、再虚构一段"教训"，引文取自它自己的正文，程序核验全过。残余风险靠逐字引文 + 独立事件 + 48 小时否决窗兜；要零风险只能回到人批。负责人几天不在，坏规矩会自动生效，只能事后否决。
- 总量到 15 条后，自动学习的新想法只进观察记录不进表（负责人手工加的第 16 条照发，publish 只警告不截断）；规则的修订／替换链路没做，现在只会追加和否决。
- 弹窗只有 Windows 有，只在登录桌面可见，不是离机告警；弹出也不证明人看过。**计划任务一定要用 `pythonw.exe` 起**：用 `python.exe` 会每轮闪一个控制台窗口，而那个窗口一旦被人关掉，正在干活的进程就被杀（原项目实测踩到，结果码 0xC000013A，脚本连一行日志都没留下）。看门狗因此会直接读计划任务的上次结果码，非 0 当场报。**看门狗自己停了没人报**（它报"通知发不出"时你正好收不到）：判断方法只有看它的日志最后一行时刻有没有超过 4 小时。
- **谁烧 token**：只有"每日学习"的提名那一步调模型，一天最多一次；写后检查与看门狗**零模型调用**。提供方用 `--provider` 选：`claude` 调本机已登录的 claude CLI（默认 sonnet，烧 `--config-dir` 那个账号，约 0.65 美元/次）；`glm` 走智谱 `GLM_API_KEY`（默认 glm-5.3，只用标准库发流式请求，端点在订阅制／充值两个里自动试）。两边的候选过同一套程序核验，换模型不会降低门槛，最坏只是通过的候选变少。原项目 09-10 实跑 glm：23 件、12 万字符 → 输入 67902／输出 21611 token，候选 3 条、程序接受 1 条。读多少正文由 `BUNDLE_CAP` 控。每次调用的模型、账号／端点、用量与花费都写进 `handoff_lessons.log`。
- 新规矩不会自动变成新的程序检查项（规矩给 AI 读，检查靠代码）。
- 效率测量 `usage_report.py` 只是原型，只读本机会话记录、只出构成比，没接进任何决策。

## 要改的常量

| 文件 | 常量 | 含义 |
|---|---|---|
| handoff_lessons.py | `SOURCES` | 哪些来源目录算判决件（本包默认是原项目的四个来源目录名，照你的目录改） |
| handoff_lessons.py | `CATEGORIES`、`DAILY_CAP`、`TOTAL_CAP`、`RULE_MAX`、`BUNDLE_CAP`、`OUT_OF_SCOPE` | 白名单类别、日增上限、总上限、一句话字数、正文预算、越界关键词 |
| handoff_notify.py | `TASK_NAMES`、`STALE_HOURS`、环境变量 `HANDOFF_OWNER` | 计划任务名、多久没成功算故障、状态页示例否决行里的名字 |
| handoff_gate.py | `is_target()` | 什么路径算交接报告（默认：路径含"工作传递"且以 `_交接报告.md` 结尾） |
| 所有脚本 | `BJ = UTC+8` | 表里的时间统一写北京时间，从带时区的时钟换算，不读本机时钟 |
