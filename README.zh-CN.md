# self-improving-handoffs · 交接写时门 ＋ 协作教训

> English: [README.md](README.md)

**这是什么**：让"多个 AI 在同一棵 docs 树里互相交接"这件事**自己变好**的一套小工具。五块：

1. **写后检查**（零 LLM）：AI 每写完一份交接报告，钩子当场查格式（G0–G7：文件名、frontmatter、状态词、必填键、时间戳、临时目录引用、链接、改冻结件），把原因回给写的那个 AI，它自己改；写索引 README 时另查链接写法（G8）；每 4 小时的兜底扫描覆盖不经钩子的写入者。
2. **共用错题本**（每天一次、无人值守）：把交接报告里挑出来的"协作机制类"错误归纳成一句话规矩，**程序核验通过的当天直接生效**。负责人看弹窗里的逐条简述，觉得不合理才去处理页点「不采纳」，当场撤下。碰到敏感形态（权限、部署、删除、密钥这类话题，带命令／网址／本机路径，零核验引文）的候选不会自动生效，等负责人点「采纳」。
3. **生效版分发**：只把当前生效的规矩（一行一条，上限 40 条）生成一份短文件，各 AI 的规则文件在**新开会话**时读到。
4. **规范扫描**（零 LLM，只列清单）：查"什么时候该写报告、写了要回流到正本、别把一次任务拆成一堆碎报告"这类流程规则，清单给 AI 开工时自查，**不弹窗**。
5. **正本写法检查**（零 LLM，第 9 版新增）：项目文档（`docs/项目情况/` 下的"正本"）写得越来越乱时能被看见。写正本时钩子只对**这一次新写进去的行**给提示（不拦人）；每 4 小时全量查一遍，比一天前新写坏了就弹一条静音知会，每周一条汇总。

外加统一入口 `handoffctl.py`（安装、体检、看状态、部署、手动跑、终端拍板）和一份给 AI 的操作手册 skill。

**解决什么问题**：规矩写在文档里，写的时候没人看；同类格式错误反复出现；每条新规矩都要人审批，改进循环转不起来；项目文档慢慢变成流水账，没人发现。

**谁该用**：有两个以上 AI 工具（Claude Code、Codex、ZCode 之类）在同一棵 docs 树里互相交接的人或团队。单人单工具用不上。

## 设计要点

- **能程序化的全程序化**。模型只在每日学习里提名候选，返回 JSON，没有任何文件写权；入表、编号、核验、发布都是程序做。
- **默认直接生效，人只在不同意或真出了问题时动手**。逐条简述＋一键撤下＋撤销，代替逐条审批。
- **证据要能机检**：候选的引文必须逐字见于原报告；要 ≥2 个独立的原始事件；类别走白名单；与已有或被拒过的规矩近似的不再进表。
- **作者自评不算证据**：读 AI 自己写的报告时，只认里面**署名引述**的负责人或审查方原话（名字后接引号，或"某某 指出："这类句式）；证据全是作者自评的候选，等负责人点「采纳」。
- **只报告、不拦人；只报确定性错误**。检查器查格式，不查内容对不对；宁可漏报，也不制造让人麻木的噪音。
- **失败要可见**："没跑成"常驻提醒；"跑成了但没东西可学"也会在体检里标出来；测试全走临时目录，不碰真实安装。
- **运行的是测过的副本**：改脚本只改正本，`test` 全过才 `promote` 进运行目录（用 MANIFEST 钉住）；钩子、计划任务、处理页按钮只跑运行版。

## 十分钟装起来

前提：Python 3.10+，`pip install pyyaml`（缺了它写后检查会 fail-closed）。每日学习另需模型，见下面"谁烧 token"。

1. 把 `规范/交接写时门/` 整目录放进你的 docs 树。教训表默认在 `docs/工作传递/协作教训.md`。
2. 把 `工作传递/交接模板.md` 放进你的 `docs/工作传递/`：写后检查从被查文件往上找这份模板取"必填键"。**模板是全量版（38 个顶层键），先按需要删键**，保留 `status`、`report_id`、`frozen_at`、`observed_at`、`related_reports`、`canonical_backflow` 这几个脚本真用到的。
3. 先跑测试：`python -X utf8 规范/交接写时门/handoffctl.py test`，七套全过再往下（非 Windows 上弹窗演练那几项记 SKIP，不算通过）。
4. **Windows**：`handoffctl.py install --dry-run` 先看它要做什么，再去掉 `--dry-run` 真装。它会建运行目录 `~/.claude/handoff/`，部署测过的运行版，写最小配置，装 Claude Code 与 ZCode 的项目级钩子，建两个计划任务（每日学习、每 4 小时巡检，都用 pythonw 起），注册处理页按钮协议，装 skill，最后跑 `doctor`。**Linux**：只装钩子与 skill，再打印建议的兜底扫描 cron 行；每日学习和弹窗只在唯一的发布者上装。
5. 验收：故意写一份第一行不是 `---` 的 `*_交接报告.md`，看 AI 有没有当场收到"G1 frontmatter 不在第 1 行"。之后随时 `handoffctl.py doctor`。
6. 告诉错题本读哪些报告：改 `handoff_common.py` 里的 `SOURCES`（别的 AI 写的评审报告所在的来源目录名）和 `SELF_SOURCES`（干活的 AI 自己写的报告目录名）。**只能有一个发布者**（一台机器跑每日学习），其他端只读生效版。
7. 规则文件加指针：Claude Code 在 `CLAUDE.md` 里 `@` 导入生效版；其他工具在规则文件里写一句"写报告前先读生效版"（`部署样例/` 里有片段）。
8. 要用正本写法检查：项目文档放在 `docs/项目情况/<项目>/` 下，每个项目一个 README（篇章表登记每篇的类型：状态、专题、依据、任务板、清单、台账、历程、历史；写明 `project_state_owner`）。没有这个目录，这一步自动跳过。

## 负责人要做的事

平时什么都不用做。

- **有新规矩生效**：一条静音通知，逐条说新规矩（一次最多三条，每条只说一次）。不合理：点通知打开处理页 →「不采纳」，当场撤下；点错了，处理页顶部「撤销」。
- **有候选没自动生效**（碰到敏感形态、或证据只有作者自评）：通知告诉你一次。有用就点「采纳」，不点就一直不生效。
- **正本写法变差**：一条静音知会，写明哪篇、哪条规则、新写了几处，或从多少字涨到多少字；也写明那次写入有没有经过写时门。点开直达处理页"正本写得怎么样"一节，有一句能转给那个项目窗口的话。每周一一条汇总。
- **需要你介入**（常驻，只留给真要你动手的事：自动学习连续 36 小时没成功、表里有程序认不出的行、表里冒出一条不是这里加的敏感规矩、生效版刷新不了、扫描没跑成）：第一行是什么事，第二行是做法。
- 不想只在"采纳／不采纳"里选：处理页每张规矩卡片都有「我有意见」，给一句能整段选中、贴给任一 AI 窗口的话。处理页还单列"生效后又被认出来的错"：规矩在、却没被照做的，说明该改写得更好懂，或做成程序检查。

弹窗只说一句话、给一个入口；规矩全文、起因、出处和按钮都在处理页。按钮走自定义 URL 协议，每个都带本机口令（种子对"动作＋编号＋规矩正文"算的 HMAC），网页、误触、记着旧编号的脚本都冒充不了。弹窗里不写内部编号和内部术语，测试要求出口兜底替换一次都不命中。

## 边界，如实说

- 写后检查是"写后提示"，拦不住写入；只查格式，不查内容对不对。项目级钩子只在从项目根启动的会话里生效，不经钩子的写入靠每 4 小时的兜底扫描。
- 新规矩是自由文本，程序证明不了它"只关于报告写法"；报告里的叙述本身也不可验证。"署名引述"只认得出明显的写法，作者把自己的话写成"负责人说："，程序分不出。残余风险靠逐字引文＋独立事件＋敏感形态硬拦＋逐条简述＋当场撤下兜着；几天不看弹窗，坏规矩会生效几天，只能事后撤。
- 正本写法检查只查脚本查得准的九条（反引号里写本机路径、自称唯一、句后追加"更新："、标题堆日期、状态篇条目缺时点或超 14 天、状态篇超 2,000 字、篇幅超 50KB、更新记录超 10 行），不判内容对不对；经过句式、跨篇重复这类要语义判断的不查。
- 总量到 40 条后新规矩暂停自动生效；规矩的修订与合并要 AI 起草方案、负责人点头。
- 弹窗只有 Windows 有，只在登录桌面可见，弹出也不证明人看过。巡检停了，每日学习会反查它的心跳；整机关机或休眠时没有任何东西会告诉你。计划任务一定要用 `pythonw.exe` 起（install 已这样装），用 `python.exe` 会闪控制台，窗口一关进程就被杀。
- **谁烧 token**：只有每日学习的提名一步调模型，一天一次（积压多时最多分 3 批）；写后检查、巡检、规范扫描、正本写法检查零模型调用。默认 `glm`：经 Claude Code 调智谱 glm-5.3（`claude -p --bare --model glm-5.3`，用 GLM Coding Plan 订阅额度；Coding Plan 只能在它支持的工具里用，所以脚本拒绝自写代码直连 `/api/coding/` 端点）；也可设 `claude`，用本机已登录的 Claude。两边的候选过同一套程序核验。

## 要改的地方

改配置不改代码：`~/.claude/handoff/config.json` 只写要改的项，其余用 `handoff_common.py` 里 `DEFAULT_CONFIG` 的默认值（`handoffctl.py config` 打印生效配置）。

| 配置 | 含义 |
|---|---|
| `paths.docs_root`、`paths.table` | docs 根与教训表位置 |
| `lessons.provider`、`lessons.model` | 提名用哪家模型（glm／claude）、哪个型号 |
| `lessons.total_cap`、`lessons.daily_cap` | 总量与每日上限 |
| `lessons.hold_sensitive` | 敏感形态的候选要不要等负责人点采纳（默认要） |
| `notify.scan_hours`、`notify.flow_days` | 兜底扫描与规范扫描的窗口 |
| `flow.path_prefix_map` | 回流路径写成另一台机器绝对路径时，映射回本机的前缀表 |

代码里的常量（都在 `handoff_common.py`）：`SOURCES`、`SELF_SOURCES`（读哪些报告）、`THIRD_PARTY_RE`（什么算署名引述）、`CATEGORIES`（类别白名单）、`OUT_OF_SCOPE`（越界关键词）、`ZB_RULES` 与 `ZB_RULES_VERSION`（正本写法的规则与版本，改了规则把版本加一，扫描会重建基线而不是成批误报）。表里的时间统一写北京时间（`BJ = UTC+8`），从带时区的时钟换算。

## 验证

- 七套 664 项回归测试，全部调生产代码、状态全走临时目录；在 Windows（Python 3.14）上跑过，CI 在 Linux 与 Windows 的 Python 3.10、3.12 上跑。弹窗 XML 由 Windows 自己的解析器演练验证；别的平台上这几项记 SKIP，不算 PASS。
- 关键修法都用变异检查证明测试真能抓到：故意把修法改回去，对应测试必须挂。第 9 版用一个仓外脚本对六处修法各做了一次（网络路径、改登记类型、他方原话、读不到的篇、超线后继续涨、改好后再犯），全部抓到。
- 自 2026-09 起在一台 Windows 电脑（发布者）上日常使用；只装检查的 Linux 一端在一台服务器上跑过，每次推送也在 CI 上跑。

它是一个可运行、有回归测试、边界写清楚的原型，不是成熟产品。
