# self-improving-handoffs · 交接写时门 ＋ 协作教训

> English: [README.md](README.md) · 仓库：https://github.com/Wyk915501/self-improving-handoffs

**这是什么**：一套让"多个 AI 一起写交接报告"这件事**自己变好**的小系统。四块：

1. **写后检查**（零 LLM）：AI 每写完一份交接报告，脚本当场查格式（G0–G7：文件名、frontmatter、状态词、必填键、时间戳、临时目录引用、链接、改冻结件），把原因回给写的那个 AI，它自己改；写索引 README 时另查链接写法（G8）；每 4 小时的兜底扫描覆盖不经钩子的写入者。
2. **共用错题本**（每天一次、无人值守）：把别的 AI 挑出来的"协作机制类"错误自动归纳成一句话规矩，**程序核验通过的当天直接生效**（第 7 版起不再有 48 小时等待）。负责人看弹窗里的逐条简述，觉得不合理才去处理页点「不采纳」，当场撤下；点错了顶部一键撤销。碰到敏感形态（权限、部署、删除、密钥这类话题，带命令／网址／本机路径，零核验引文）的候选**不会自动生效**，等负责人点「采纳」。
3. **生效版分发**：只把当前生效的规矩（一行一条，上限 40 条）生成一份短文件，配置了指针的宿主在**新开会话**时读到。**发布不等于使用**：只对加了指针的宿主生效；规则只在会话启动时载入；读没读、照没照做，程序都证明不了。
4. **规范扫描**（零 LLM，只列清单）：对"什么时候该写报告、什么时候只改不写、别把一次任务拆成一堆碎报告"这类流程规则做机器检查（W2 报告声明回流但正本没动、W3 同目录短窗口一堆新报告，默认开；W1 改了正本没留报告默认关，要加 --w1，而且只看原项目的 docs/项目情况/ 目录），清单给写报告的各 AI 开工时自查，**不弹窗打扰负责人**。

外加第 7 版的**统一入口** `handoffctl.py`（安装、体检、看状态、部署、手动跑、终端拍板）和一份给 AI 的操作手册 skill。

**解决什么问题**：规矩写在文档里没人在写的时候看；同类格式错误反复出现；每条新规矩都要人审批、循环转不起来。

**谁该用**：有两个以上 AI 工具（Claude Code／Codex／ZCode 之类）在同一棵 docs 树里互相交接的团队。单人单工具用不上。

**设计原则**（原项目负责人原话）："我需要一个更自动化的，即使任务能力缩小" / "我要的是一个自动的东西，只有他出了问题才需要我介入" / "应该就是默认直接生效；然后弹窗简述改动，我会看改动，不合理的话我才会点进去看"。所以：能程序化的全程序化；模型只出候选、没有文件写权；人只在不同意、或真出了问题时动手。

**先说清验证范围**：这套东西在原项目的一台 Windows 11 电脑（唯一发布者）和一台 Linux 服务器（只装检查）上从 2026-09-08 起连续使用。Claude Code 的钩子两端都实测触发过；**ZCode 的钩子只验了配置能装、没实测它真的触发**。每日学习真实跑过多轮；原项目负责人在处理页亲手采纳过 20 多条被拒候选、在用的规矩 30 多条。第 7 版的全部 530 项回归测试在 Windows（Python 3.14 与 3.12）上跑过；弹窗 XML 由 Windows 自己的解析器演练验证过。**第 7 版的新弹窗与处理页尚未在真机上点过一轮**（原项目随后部署），经 Claude Code 调 GLM 的新通道只跑过一次演练（真实调用、不写表）。它不是成熟产品，是一个可运行、有回归测试、边界写清楚的原型。

## 十分钟装起来

前提：Python 3.10+，`pip install pyyaml`（缺了它写后检查会 fail-closed 拦所有报告）。每日学习另需模型：默认经已安装的 Claude Code 调智谱 GLM（见下面"谁烧 token"），或用本机已登录的 Claude。

1. 把 `规范/交接写时门/` 整目录放进你的 docs 树（脚本按自己的位置找同目录的提示词与测试，教训表默认在 `docs/工作传递/协作教训.md`）。
2. 把 `工作传递/交接模板.md` 放进你的 `docs/工作传递/`——写后检查从被查文件往上找这份模板取"必填键"清单。**这份模板有 38 个顶层键**，是原项目多 AI 循环用的全量版；**先按你的需要删键**（保留 `status`、`report_id`、`frozen_at`、`observed_at`、`feedback_for`、`related_reports`、`canonical_backflow` 这几个脚本真用到的；删了 `canonical_backflow` 就等于关掉规范扫描的 W2），不然写报告的成本会比你想象的高。
3. 先跑测试：`python -X utf8 规范/交接写时门/handoffctl.py test`（六套全过再往下；非 Windows 上弹窗演练那几项记 SKIP，不算通过）。
4. **Windows**：`python -X utf8 规范/交接写时门/handoffctl.py install --dry-run` 先看它要做什么，再去掉 `--dry-run` 真装——建运行目录 `~/.claude/handoff/`、部署测过的运行版、写最小配置、装 Claude Code 与 ZCode 的项目级写后检查钩子、建两个计划任务（每日学习北京 09:00、巡检每 4 小时，pythonw 起、允许电池）、注册处理页按钮协议、装 skill，最后跑 `doctor`。**Linux**：install 只装钩子与 skill，再打印建议的兜底扫描 cron 行（每日学习与弹窗只在唯一的发布者上装）。
5. 验收不是看配置：故意写一份第一行不是 `---` 的 `*_交接报告.md`，看 AI 有没有当场收到"G1 frontmatter 不在第 1 行"。之后随时 `handoffctl.py doctor` 体检。
6. 要错题本自动跑：改 `handoff_common.py` 里 `SOURCES`（哪些来源目录算"别的 AI 的判决件"）。**只能有一个发布者**（一台机器跑每日学习），其他端只读生效版。
7. 规则文件加指针：Claude Code 在 `CLAUDE.md` 里 `@` 导入生效版；其他工具在它的规则文件里写一句"写报告前先读生效版"（`部署样例/` 里有片段）。

改脚本以后：只改正本 → `handoffctl.py test` → `promote`（测试全过才复制进运行版并用 MANIFEST 钉住）→ `doctor`。自动任务、钩子、按钮只跑运行版，改到一半的正本不会被执行。

## 负责人要做的事

平时什么都不用做。

- **有新规矩生效**：右下角一条静音通知，逐条说新规矩（一次最多三条，每条只说一次）。觉得不合理：点通知打开处理页 →「不采纳」，当场从生效版撤下；点错了，处理页顶部点「撤销」。
- **有候选没自动生效**（碰到敏感形态）：通知告诉你一次。有用就在处理页点「采纳」；不点，它就一直不生效。
- **需要你介入**（常驻通知，只留给真要你动手的事：自动学习连续 36 小时没成功、表里有程序认不出的行、表里冒出一条不是这里加的敏感规矩、生效版刷新不了、规范扫描没跑成）：第一行是什么事，第二行是做法——多半是"把这句话贴给任一 AI 窗口：帮我跑协作教训的体检 handoffctl.py doctor"。
- 偶发的小状况（某一轮没跑成、表满了、积压多）只发一条静音通知、24 小时后自己消失；连续没成功才会升级成"需要你介入"。

**弹窗与处理页的分工**（Windows）：弹窗只说一句话、给一个去处理页的入口；规矩全文、为什么会有这条、出处，以及「不采纳」「采纳」「恢复」这些按钮都在处理页上。按钮走一个自定义 URL 协议，每个按钮都带本机口令（种子对"动作＋编号＋规矩正文"算的 HMAC），网页、误触、记着旧编号的脚本都冒充不了；终端里推翻负责人已做的决定还要显式 `--confirm-held`。**弹窗里不写内部编号和内部术语**——测试要求出口兜底替换一次都不命中。原项目负责人的原话是"我压根不知道 LG-06 是什么"。

其余都不需要人：候选由模型提名、程序核实——引文必须逐字见于原文；证据须来自 ≥2 个不同原始事件，且引用的原件必须在树里实存、且不在判决件来源目录里（只验存在，不验相关）；类别白名单；每天自动新增 ≤6 条、总量 ≤40 条。**越界关键词与注入形态的硬拦只是自由文本之上的额外一层：换个说法就绕得过，反过来也会误拒合法教训**——真正的兜底是逐条简述＋当场撤下。

## 边界，如实说

- 写后检查是"写后提示"，拦不住写入；只查格式，不查内容对不对。程序检查通过 ≠ 报告写得对。
- 只对**接了钩子的宿主**即时生效；不经钩子的写入者靠每 4 小时的兜底扫描。项目级钩子只在从项目根启动的会话里生效。
- 链接检查（G6）只证明**本机**存在；扫描模式忽略本机断链，只保留另一台机器必断的写法（反斜杠、本机绝对路径）。
- 新规矩是自由文本，程序证明不了它"只关于报告写法"；判决件的叙述本身也不可验证。残余风险靠逐字引文＋独立事件＋敏感形态硬拦＋逐条简述＋当场撤下兜；负责人几天不看弹窗，坏规矩会生效几天，只能事后撤。
- 表外直接写进表的行：程序有本机账本认得出"不是这里加的"，碰到敏感形态的先不发布、请负责人确认，没碰到的照发并告知一次。能读本机状态文件的程序拿得到口令种子——它本来就能直接改表。
- 总量到 40 条后新规矩暂停自动生效（每周告知一次）；规矩的修订／合并链路没做成自动的，表满后的合并靠 AI 起草方案、负责人点头。
- 弹窗只有 Windows 有，只在登录桌面可见，不是离机告警；弹出也不证明人看过。巡检自己停了，每日学习会反查它的心跳（只认计划任务那一轮），超过 12 小时没巡检就常驻提醒一次；整机关机或休眠时没有任何东西会告诉你。**计划任务一定要用 `pythonw.exe` 起**（install 已这样装）：`python.exe` 每轮闪一个控制台，那个窗口一被关掉，正在干活的进程就被杀（原项目踩过：结果码 0xC000013A，脚本一行日志都没留下）。
- **谁烧 token**：只有每日学习的提名那一步调模型，一天一次（积压多时同一轮最多分 3 批）；写后检查、巡检、规范扫描**零模型调用**。默认 `glm`：**经 Claude Code 调用**智谱 glm-5.3（`claude -p --bare --model glm-5.3`，指向智谱的 Anthropic 兼容端点，用 GLM Coding Plan 订阅额度）——智谱规定 Coding Plan 只能在它支持的工具里用，自写脚本直连 coding 端点不合规，所以脚本拒绝任何 `/api/coding/` 端点；要自写脚本直连只能用按量计费的标准端点（配置 `lessons.glm_via` 设 `api`）。也可用 `claude`：本机已登录的 Claude（默认 sonnet）。两边的候选过同一套程序核验，换模型不会降低门槛。每次调用的模型、用量写进日志，模型坏输出原文存 logs/raw/。
- 新规矩不会自动变成新的程序检查项（规矩给 AI 读，检查靠代码）。
- 效率测量 `usage_report.py` 只是原型，没接进任何决策。

## 要改的地方

改配置不改代码：`~/.claude/handoff/config.json` 只写你要改的项，其余用 `handoff_common.py` 里 `DEFAULT_CONFIG` 的默认值（`handoffctl.py config` 打印生效配置）。常见的：

| 配置 | 含义 |
|---|---|
| `paths.docs_root`、`paths.table` | docs 根与教训表位置 |
| `lessons.provider`、`lessons.model` | 提名用哪家模型（glm／claude）、哪个型号 |
| `lessons.total_cap`、`lessons.daily_cap` 等 | 总量与每日上限 |
| `lessons.hold_sensitive` | 敏感形态的候选要不要等负责人点采纳（默认要） |
| `notify.scan_hours`、`notify.recent_days`、`notify.snooze` | 兜底扫描窗口、处理页"最近生效"天数、常驻提醒加"稍后提醒"（默认关） |

代码里的常量：`handoff_common.py` 的 `SOURCES`（判决件来源目录）、`CATEGORIES`（类别白名单）、`OUT_OF_SCOPE`（越界关键词）；`handoff_gate.py` 的 `is_target()`（什么路径算交接报告）。表里的时间统一写北京时间（`BJ = UTC+8`），从带时区的时钟换算，不读本机时钟。

## 来历

从一个更重的"自我改进循环"设计收缩而来（原设计有 sha 级证据链、三轨信号、三周期试点合同，跑了两天一拍都没成；2026-09-08 负责人否定后一天内重做）。之后经过多轮对抗复核；第 7 版是一次全面审查（50 条问题、两轮独立复核）加环境化与弹窗重做的结果。各轮挑了什么见 `设计要点与审查史.md`。
