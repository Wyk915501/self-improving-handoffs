# 交接写时门（自我改进循环）

**为什么存在**：写交接报告的格式规矩早就写在[交接模板](../../工作传递/交接模板.md)和[工作传递总规则](../../工作传递/README.md)里，同类错误照样反复出现；几个 AI 互相挑错的报告里也一直有"下次别再这样"的经验，却没人收起来。这套东西做三件事：写报告时当场自查；每天把互相挑错的经验总结成规矩；规矩直接生效，发给每个 AI 读。

**谁该看**：负责人看第一节就够；维护它的 AI 看第二节起；在新机器上安装的人看第三节。

**什么时候看**：弹窗看不懂时；想撤一条规矩时；它报错、要改它或要装它的时候。

## 一、给负责人：一页讲完

它每天自己转，你只在不同意的时候动手。

| 什么时候 | 发生什么 | 你要做什么 |
|---|---|---|
| 每天早上 9 点 | 读前一天 AI 互相挑错的报告，总结出新规矩，**直接生效**，以后 AI 写报告前都会读到 | 不用做 |
| 有新规矩生效 | 右下角弹一条静音通知，逐条说新规矩是什么（一次最多三条，其余下一轮说），每条只说一次 | 觉得不合理：点这条通知 →「不采纳」，当场撤下 |
| 碰到敏感话题的候选 | 涉及权限、部署、删除、密钥，带命令、网址、本机路径，或者原文里一句都对不上的候选**不会自动生效**，弹一条告诉你 | 有用就点「采纳」；不点，它就一直不生效 |
| 表里冒出一条不是这里加的规矩 | 别的机器或窗口直接往表里写了一行、还碰到了上面那些敏感形态，**先不给 AI 读**，常驻弹窗请你看 | 没问题点「确认生效」，不该有点「不采纳」 |
| 表里冒出一条不是这里加的、但没碰到敏感形态的规矩 | 照常生效，普通弹窗告诉你一次 | 不合理就「不采纳」 |
| 出了要你处理的问题 | 常驻弹窗「需要你介入」：先写是什么事，再写做法（多半是"把这句话贴给任一 AI 窗口：……"） | 照做法做；点「去处理」直达处理页「要你做的事」，解决前一直列着 |
| 偶发的小状况 | 某一轮没跑成、表满了、积压多这类：静音通知，24 小时后自己从通知中心消失 | 不用做；连续 36 小时没成功才会升级成「需要你介入」 |

几个数：每天自动新增最多 6 条；规矩总数上限 40 条，满了每周告知一次（不常驻），想腾地方就让 AI 起草一份合并方案给你点头。

处理页上的按钮都带本机口令，网页或别的程序冒充不了你。点完处理页会自己刷新，顶部写着刚才做了什么；点错了就点那里的「撤销」。最近 30 天撤下的规矩和候选也都能点「恢复」。

要暂停每天的总结：在 PowerShell 里停用计划任务 HandoffDaily（恢复就重新启用）；写报告时的自查和弹窗不受影响。

一个盲区：通知是这台电脑自己发的。关机、长时间睡眠或看门狗被停用时，没有任何东西会告诉你；处理页最下面写着"巡检上次按计划运行"的时刻（超过 9 小时标红），隔几天看一眼即可。

**正本与运行版**：本目录是正本，跨机同步，可以随时改。本机的两个计划任务、两处钩子、处理页按钮跑的是运行目录里的**运行版**（`~/.claude/handoff/bin/`）：`handoffctl.py promote` 先跑六套测试，全过才从正本复制过去，并用 MANIFEST.sha256 钉住每个文件。好处有两个：改到一半的正本不会被自动任务执行；从别的机器同步下来的代码改动，也要本机显式 promote 才会跑。代价是改完脚本要多敲一条命令，`status` 与 `doctor` 会点名"运行版落后于正本"。

**运行目录** `~/.claude/handoff/`：

| 子目录 | 放什么 |
|---|---|
| bin/ | 运行版代码、MANIFEST.sha256、SOURCE（指回正本）、VERSION |
| state/ | 每日学习进度、看门狗提醒记录与处理页口令种子、被拒候选池、锁 |
| logs/ | 两份日志（超过 1 MB 自动轮转一份）；raw/ 存模型坏输出原文，便于事后诊断 |
| pages/ | 处理页、细节页、弹窗图标 |
| config.json | 本机配置，只写要改的项；没写的用 handoff_common.py 里 DEFAULT_CONFIG 的默认值 |
| backup/ | install 改钩子配置前的备份 |

机密：GLM_API_KEY 只放在用户环境变量里；处理页口令种子在 state/notify_state.json。两样都永不同步、永不打印、不进分享包。

**数据**（都在 [docs/工作传递/](../../工作传递/README.md)，跨机同步）：[协作教训](../../工作传递/协作教训.md)（带出处的完整表）、[协作教训-生效](../../工作传递/协作教训-生效.md)（生效版，被 .claude/CLAUDE.md 引入）、[协作教训-否决记录](../../工作传递/协作教训-否决记录.md)（只认表格行）、[写后检查-待处理](../../工作传递/写后检查-待处理.md) 与 [规范扫描-待处理](../../工作传递/规范扫描-待处理.md)（每台机器写自己那份，US3 的带 -US3 后缀）。

## 三、安装、体检与日常操作

一切走统一入口。Windows 用 `py -X utf8 <路径>/handoffctl.py <子命令>`；US3 用 `python3 -X utf8`。已安装时用运行版 `~/.claude/handoff/bin/handoffctl.py`，改脚本与部署时用正本这一份。

| 子命令 | 做什么 |
|---|---|
| status | 一屏看全：两个任务上次跑得怎样、下次何时跑、积压、生效条数与上限、最近生效的规矩、等你点的候选、表体检、运行版是否最新 |
| doctor | 只读体检，逐项 ✓ / ! / ✗：Python 与 PyYAML、运行目录、配置、运行版完整性、计划任务、处理页协议、GLM_API_KEY 是否存在、Claude Code 能不能找到（每日学习经它调 GLM）、两处钩子、skill、CLAUDE.md 引入、表体检、生效版凭证、两个心跳、锁、日志大小、时区。退出码 0＝没有 ✗ |
| test | 跑六套回归测试，打印被测文件的 SHA（LG-08） |
| promote | 跑测试，全过才把正本复制进 bin/；装过 skill 的顺带把操作手册同步过去 |
| install | 建运行目录、迁移旧状态文件、写配置、promote、把计划任务与两处钩子与处理页协议改指运行版、装 skill、跑 doctor；`--dry-run` 只说不做；可重复执行 |
| uninstall | 删计划任务、协议、两处钩子、skill；不加 `--yes` 只列清单；状态与日志保留，`--purge` 才删运行目录 |
| run daily / check / publish / promote-rules / adopt-pool / scan / flow | 手动跑一次，与计划任务同一入口、同一配置、同一把锁；daily 会调模型、烧 GLM 额度，跑完顺带巡检一轮（新规矩当场简述，不用等下一轮；这一轮不算巡检的心跳） |
| trust LG-xx [--confirm-held] | 确认一条表里冒出来、不是本机流程加的规矩可以生效：不加参数只打印全文与被扣下的原因；负责人当面点名这一条后加 --confirm-held 才放行（可一次给多个编号） |
| evidence-stats | 证据主通道在真实树上的放行率 |
| veto LG-xx 理由 | 终端里不采纳（当场重发布） |
| confirm LG-xx --confirm-held | 看过了（以后不再简述它）——负责人就收不到这条的简述了，所以终端里要 --confirm-held |
| unveto LG-xx --confirm-held / undrop RP-xx --confirm-held | 恢复负责人不采纳过的规矩（删否决记录那一行、恢复原状态、当场重发布）／把负责人点过「不用」的候选恢复成候选。这是推翻负责人已做的决定，终端必须加 --confirm-held；处理页上的「恢复」「撤销」按钮带口令，不需要 |
| adopt RP-xx [--confirm-held] / drop RP-xx | 采纳／不用一条被拒候选。拍板类命令终端没有口令可核、谁都能敲：只在负责人当面明确要求时用，署名写"未核实是谁敲的"；采纳"等负责人看一眼"的候选还要 --confirm-held |
| table-check | 表体检：认不出的状态格、错列、编号重复、否决记录里不在表格内的行、生效版凭证 |
| logs lessons\|notify -n 40 | 看日志尾巴 |
| config | 打印生效配置与各文件位置 |

**改了脚本以后**：只改正本 → `test`（六套全过）→ `promote` → `doctor`。三步缺一不报"已修好"；自己改自己测的写"已改，待复验"（LG-29）。

**install 具体做什么**：
0. 先查四件事，任一不过就不装：当前 Python 装了 PyYAML、旁边有 pythonw；没有每日学习进程正持着锁；两个计划任务都不在运行。
1. 先跑六套测试、部署运行版（promote，只建 bin/）。测试不过就停：state/ 都不建——state/ 一出现，新代码就改读新布局。
2. 旧布局（`~/.claude/tools/handoff_*`）的状态文件复制进 `state.staging/` 并比对哈希，**原件不动**；全部成功才整目录改名成 `state/`，中途失败就删掉暂存目录，还是旧布局。日志与图标只在运行目录里没有时复制，出错只提示（日志正被追加时哈希本来就对不上）。重装时（state/ 已在）原件仍是权威、照样覆盖上次半途而废的副本；早已留底过、原处又冒出来的不拿它覆盖现行状态。
3. 没有 config.json 就写一份最小的（本机 docs 根、教训表、提名模型）。
4. Claude Code（`.claude/settings.local.json`）与 ZCode（`.zcode/config.json`）的写后检查钩子改指运行版的 handoff_gate.py，加 `-B`；改前备份到 backup/、改后回读确认；别的钩子（比如工作流写时门）一个不碰。
5. 两个计划任务换动作（`pythonw -X utf8 -B <bin>/handoffctl.py run daily｜run check`）和设置：允许用电池启动、拔电不停，上限 90／30 分钟，错过了开机补跑，同一时刻只跑一份；**原触发时刻保留**（它按 UTC 锚定，本机时区变了也是北京 09:00）。没改成就停：旧任务仍跑旧脚本、旧状态原件还在，修好重跑 install。
6. 处理页协议 `handoff-rule:` 重新注册到运行版。
7. 计划任务已改指运行版，这时原件才改名 `*.migrated-日期` 留底（复制之后若又被旧任务写过，先重新复制），留底副本里的口令种子剥掉——剥种子放在最后，任何一步失败都不会毁掉唯一带种子的那份。
8. skill 复制到项目 `.claude/skills/handoff-loop/`。
9. 跑 doctor。

US3（Linux）上 install 只做 1–4 与 8，再打印建议的 cron 行；每日学习与弹窗不在 US3 装（单一发布者在 Windows）。

## 四、写后检查查什么（handoff_gate.py v2.8）

只对路径含"工作传递"、文件名以 `_交接报告.md` 结尾、且不在 `_archive/` 里的文件查 G0–G7；对 `工作传递/**/README.md`（非 `_archive`）只查 G8。它是"写后提示"：钩子在文件写入之后跑，把原因回给写的那个窗口；拦不住写入，也管不到 Bash、同步脚本、Codex 等别的写入来源——那些靠看门狗每 4 小时的兜底扫描。

| 编号 | 查什么 | 为什么 |
|---|---|---|
| G0 | 文件名含反斜杠 | Windows 分隔符混进 Linux 文件名，文件不在目录里、索引找不到 |
| G1 | frontmatter 从第 1 行开始、200 行内闭合、是合法 YAML 映射、无重复键、无坏值；报错带**文件行号、列号与改法**；认得出 BOM | 状态行写在 `---` 前面整个表头失效；以前只给一句 PyYAML 报错首行，看不出错在哪 |
| G2 | status 只能是 draft 或 ready_for_review | 处置写在索引里，报告自身不用别的状态词 |
| G3 | 模板顶层键齐全（读仓内交接模板；full_contract_finalize 仅 multi-ai-loop/v1 必填） | 缺键就无法按编号追溯 |
| G4 | ready_for_review 时两个时刻带时区；frozen_at 不得晚于现在（提示点出时区换算这个常见成因，见 LG-02）；observed_at ≤ frozen_at | 冻结时刻写 none 等于没冻；写在未来叫预盖 |
| G5 | 正文不引用会话临时目录（同行写 gate:allow-temp 可豁免） | 复核方打不开 |
| G6 | 相对链接在本机能打开 | 只证明本机存在；扫描与清单滤掉这一类（跨机同步滞后） |
| G6P | 链接含反斜杠，或写成本机绝对路径（盘符、file:、/root/、~/） | 写的人能打开、另一台机器打不开；扫描不滤这一类 |
| G7 | （钩子模式，提示）改的是已冻结的件：按钩子载荷里的原件判断——原件已 ready_for_review 且冻结超过 30 分钟就提示，新版把 status 改回 draft 也照样提示；新建文件不报 | 冻结件不回改，要改另写前向更正件。载荷里拿不到原件时退回按新版的 frozen_at 年龄判 |
| G8 | 索引 README 的链接：①解释合法转义后仍含反斜杠；②同目录裸文件名本机找不到（只在扫描时报）；③多带了自己所在目录作前缀。`_archive/<文件名>` 不算③ | 归档后索引行按规范写 `_archive/<文件名>`；`_archive` 不跨机同步，本机找不到是不对称，照"只写裸文件名"去改会把对端的链接改断 |

钩子回给 AI 的抬头按问题类型说话：冻结件写"不要就地改内容，另写前向更正件"；只有提示时写"提示"；写索引时叫"索引链接检查"；ZCode 的兜底扫描写"不一定是你写的，不是你写的别动"。载荷深搜跳过正文字段（含 Claude Code 的 oldString、newString、originalFile、structuredPatch），正文里出现别件的路径不会劫持检查对象。

手动跑：`handoffctl.py run scan`，或 `py -X utf8 docs/规范/交接写时门/handoff_gate.py --scan docs/工作传递 --since 24`。

## 五、每日学习（handoff_lessons.py v3.10）

一个入口 daily，加锁串行四步。模型全程没有任何文件写权，只返回候选。

1. **收信号（collect）**：按上次扫描位置加积压队列，枚举评审方（codex、claude-code-US3-claude、Zcode-glm、claude-code-glm 四个来源目录）的新判决件，正文当**不可信引文**送给模型；分隔符每轮随机，正文里出现分隔串的件整件剔除。模型返回后**才读表**、逐条核验：rule 与 why 必须是字符串（模型给 null 当缺失）；不越界、不带注入形态；≤60 字；类别在九类白名单；与现有、已否决、本批已接受都不近似；引文逐字见于该判决件原文（忽略空白与引号样式）；≥2 条证据来自不同判决件且指向 ≥2 个树内实存、不在评审来源目录里的原始事件（认 YAML 块列表、行内列表、路径写法）；当天自动新增未满 2 条、总量未满 40 条。全过的**当天写成生效行**；没过的记观察，除垃圾与重复外入被拒候选池（带结构化拒因码）。
2. **否决同步（promote）**：否决记录表格里点名的行，状态格同步为「否决（见否决记录；原：原状态）」；否决记录里删掉那一行＝撤销，状态格恢复原状态；遗留的标准拟生效行到期转生效；认不出的状态格当场报错（LG-30 的教训）。
3. **池补入（pool-adopt）**：软拒因（证据不足但至少一条引文逐字对得上、类别不合、配额、61–90 字）同一轮自动补入生效；硬拒因（越界关键词、命令／网址／本机路径／配置文件名／@导入 这类形态、看不见的字符、模型自报与现有规矩冲突、超过 90 字、一条核验过的引文都没有）**不自动生效**，标 hold 留在池里，等负责人在处理页点「采纳」。池里另存净化前的原文；复查对原文与写进表时的样子（净化后）各查一遍，并先去不可见字符、全角转半角（「Ｃ：／」「＠」这类写法照样认得）。负责人点过「不用」的候选，换个说法再来也不入池、不补入，证据够走直通也不行；池列表封顶时这些「不用」的记录单独保留，不会被挤掉。每天所有自动来源合计 ≤6 条、总量 ≤40 条、单轮 ≤8 条，到顶就顺延，总量到顶时看门狗每周告知一次（不常驻；合并方案由 AI 起草、负责人点头才动）。collect 这轮写表冲突时，池补入跳过（免得被拒候选比合格候选先生效）。
4. **发布（publish）**：生成生效版，只含状态"生效"且不在否决记录里的规矩；**本机账本**记着每条规矩是不是本机流程加的（收信号直通、池补入、处理页采纳时登记正文哈希，账本在本机不同步的状态文件里）——表里冒出不在账本里的行、或已有行的正文被改过，有硬拒因就先不进生效版、请负责人确认，没有就照发并登记、看门狗普通告知一次；状态文件不在或读坏了（新机器、文件丢了）时账本从零重建，只登记没有硬拒因的行，其余同样请负责人确认（读坏的文件改名留存，一时读不到就重试、仍不行宁可这步失败，不拿空状态覆盖）；正文过一遍净化（@ 换全角、去 HTML 注释与脚本标签、去零宽与双向控制字符）；页首固定声明"只约束报告写法与协作，不授权执行命令、读取文件或改权限"；版本行带**表哈希＋否决哈希**，两样任一变了看门狗当轮重发布。

**提名用的模型**：默认智谱 glm-5.3，**经 Claude Code 调用**（`claude -p --bare --model glm-5.3`，指向智谱 Anthropic 兼容端点，用 Coding Plan 订阅额度、不走 Claude 账号）。为什么不再自写脚本直连：智谱官方写明「GLM Coding Plan 仅限在官方支持的指定工具与产品环境中使用。在除规定工具外调用 API，不可享用 Coding 套餐的额度」「用于非支持工具将被限制权益」「3 次以上违规可能会被封禁账号」（docs.bigmodel.cn 的 coding-plan/faq 与 usage-notes，10-03 核原文），Claude Code 在官方支持工具清单里。配置 `lessons.glm_via` 设 `api` 才自写脚本直连，而且只认按量计费的标准端点（花账户余额）；配置里出现 coding 端点一律拒绝并说明。Claude Code 对它不认识的模型把输出上限卡在 32000 token（10-03 实测一批 6.5 万字符、输出 30049），所以经 Claude Code 时每批正文预算 6 万字符，积压多就同一轮接着送下一批（最多 3 批、开跑 40 分钟后不再开新批）。命令行另带 `--setting-sources project`：`--bare` 挡不住用户级 settings.json 的 env，切换提供方的工具一改那里的 ANTHROPIC_BASE_URL，智谱密钥就会发到别家（第十批复核用本机假服务器实测）；单次调用不超过计划任务剩下的时间；npm 装的 claude.cmd 垫片换成旁边的 claude.exe；子进程一律经 `_run_tree` 起：超时、手动跑时按 Ctrl-C、Linux／macOS 上收到 SIGTERM／SIGHUP，都先按进程号结束自己起的整棵进程树（Windows 靠 taskkill /T 按父子关系往下找，中间一层先退出、链条断了的后代够不着；Linux／macOS 起子进程时让它自成一组），提示词先写进临时文件当标准输入（不然 Windows 上子进程卡在读输入之前时，时限管不住）。请便宜模型修语法的那一次也按同一规则分：连不上、限频算这一轮失败；交回的 JSON 没有 candidates 列表一律按输出坏了处理，不当成「0 条候选」把这批报告记成已读（第十一批）。连不上、超时、认证失败都算这一轮失败；只有认得出的截断与轮数用尽才按"输出坏了"处理。glm-5.3 官方不能关思考、没有思考预算参数（只有 reasoning_effort），按默认用。改用本机 Claude 账号：`lessons.provider` 设 `claude`，默认 sonnet、功率 max。模型输出坏 JSON 或被截断时：先本地修（没转义的引号、尾逗号、代码围栏）→ 再让 glm-5.3-flash 只修语法（同样经 Claude Code） → 仍失败把原文存进 logs/raw/，这批排到队尾、下轮批量减半换个组合再试；只有单件一批的失败才算到那一件头上，连续 3 次才跳过它；整个收信号连续 3 次失败才算这一步失败（之前的只记日志、自动重试）。证据主通道（≥2 个原始事件）在真实树上的放行率约 15%（`handoffctl.py evidence-stats`）——多数判决件只引别的判决件、不引原件；所以这道门实际上决定的是候选走直通还是走被拒候选池，池里仍要至少一条引文逐字对得上。

**程序守不住的两条**：①候选规矩是自由文本，程序无法证明它只关于"报告写法与协作"；②判决件的叙述本身无法验真——"原件实存"只验存在不验相关。兜底：注入形态与越界话题硬拦、每条新规矩当天逐条简述、处理页「不采纳」当场撤下、否决记录随时可加。负责人 09-08 接受这项残余风险时依据的"48 小时否决窗"已于 09-29 按负责人裁定取消，兜底换成了上面这几条；10-03 负责人授权代定，保留"碰到敏感形态的候选要负责人点「采纳」"这道例外（配置 `hold_sensitive` 可关），理由与取舍见第十批交接报告。

## 六、看门狗（handoff_notify.py v1.14）

每 4 小时一轮（每日学习跑完也顺带一轮）：读表与状态 → 判断要不要提醒 → 去重后弹窗 → 重写处理页与细节页。一轮最多两条弹窗：「需要你介入」一条＋新规矩简述一条；两样都没有时，告知类合成一条。

| 弹窗 | 什么时候 | 样子 |
|---|---|---|
| 需要你介入 | 自动学习连续 36 小时没成功、表里有认不出的行或坏字节、表里冒出不是本机加的敏感规矩、生效版连续 3 轮刷新不了、规范扫描或写后检查扫描没跑成（含超时）、写后检查待处理清单写不出 | 常驻、出声，点掉才消失；第一行是什么事、第二行是做法（贴给 AI 的那句话），同一轮别的事挤得下就跟在后面；之前提醒过、还没解决的另写"要你做的事一共 N 件"；点正文或「去处理」直达处理页「要你做的事」 |
| 新规矩简述 | 最近新生效的规矩、表外加进来又照常生效的规矩 | 静音普通通知，逐条列正文，一次最多三条（只给真列出来的记"已简述"，其余下一轮说）；同一批的新通知替换旧的 |
| 只是告知 | 某一轮没跑成、被系统终止或开跑后没跑完（下一轮会再跑）、上次运行出错、教训表满了（每周一次）、同一窗口一天 ≥3 份报告没过写后检查、有候选没自动生效、不采纳记录在别处被改（多了或少了几条）、终端里替你做了决定（未核实是谁敲的）、手写的老格式规矩快到点或已到期、待读积压超过 60 件 | 静音，24 小时后从通知中心消失；只在这一轮没有前两种弹窗时发，挤不进的下一轮接着说；还有要你做的事没解决时标题不说"不用你做事" |
| 点按钮后的回执 | 处理页上点了「不采纳」「采纳」「撤销」等 | 静音，1 小时后消失；口令不对、表正忙这类"没生效"的回执出声、留 24 小时 |
| 不弹窗，只上处理页 | 规范扫描的新发现（给写报告的各 AI 窗口看的，它们开工先读清单自查；10-03 负责人问"又跳了，我该怎么做"后改）；按不采纳记录撤下规矩（自己点的当时已有回执，别处同步来的由告知类说） | 处理页「系统自己在做的」逐行写明 |

弹窗文字一律不出现内部编号与内部词（「LG-12」「否决」「每日学习」「看门狗」、任务名、十六进制结果码）：调用点自己写人话，`toast()` 出口另有一道兜底替换（common.TOAST_INTERNAL），命中会记日志、测试要求一次都不命中。弹窗 XML 由 Python 生成：文字全部转义、去掉 XML 不允许的控制字符，标题 ≤60 字、正文 ≤4 行，总长硬上限 4800 字节；整段经环境变量交给 ps1（不拼命令行），子进程不继承名字像密钥的环境变量。ps1 只管送达，另认同类替换（tag/group）、过期时间、直接进通知中心三个可选项；不给 XML 的老调用方（antd 周检）行为逐字节不变。

- **计划任务结果码按语义判**：正在运行、排队、还没跑过都不算失败（唤醒补跑时两个任务同时起，以前会误报"没成功"）；被系统终止、被禁用、条件不满足才报，说清原因，时刻换算成北京时间。脚本自己记了错误退出的，只报一条。
- **处理页**：第一屏只回答"现在要不要你"——要你做的事一直列着、附做法，直到解决；下面依次是等你确认的、等你看一眼的候选、最近生效（不用点）、待自动补入的候选、最近 30 天撤下的（能恢复）、系统自己在做的。点完按钮同一张卡的按钮置灰、显示"已发出"，3 秒后自己刷新；顶部「刚才的操作」写着结果并带「撤销」。拍板后当场重写时，「要你做的事」里表外规矩与生效版凭证两类按现状重算；巡检跑着时你点了按钮，这一轮写出的页面按点完的样子。页面只有一段固定脚本（CSP 只放行它的哈希，不内联事件，不以程序方式唤起协议）；规矩原文一律转义；出处与候选证据里的链接只放行 docs 下实存的 .md，而且先做纯字符串判断再碰文件系统（`\\主机\共享` 这类写法让本机去连 SMB：第十批复核实测会真去连网，连不上就抛错让巡检整轮崩；对端是恶意主机时还可能带出本机凭据——这一层是推断，没抓包）。
- **处理页按钮**：七个动作（看过了、不采纳、确认生效、恢复、采纳、不用、恢复为候选）都带口令＝本机种子对"动作＋编号＋正文"算的 HMAC 前 10 位；正文变了口令自动作废，不含日期（昨晚开着的页面今天照样能点）。没口令或口令不对的一律不改任何文件，弹一条"这次点击没有生效"（同一小时最多弹 3 次，免得被网页刷屏）。表里冒出来的敏感规矩另有「确认生效」按钮（同样带口令）；终端确认要 `trust LG-xx --confirm-held`。看门狗每轮先刷新生效版、再读账本，被扣下的行不会被当成「新规矩已生效」简述出去。
- **不采纳当场撤下**：写进否决记录后立刻重发布生效版；「看过了」只是不再简述它，处理页仍列着、标「你看过了」、随时还能撤。不采纳记录在别处多了或少了几条，告诉你一次；「少了」只有在这条最近一次记进本机已知之后你点过「恢复」才不说（记的是巡检读否决记录的时刻：巡检跑着时你点的「恢复」也算你的；第十一批）。只有生效版混进坏字节时当轮重新生成（它是程序生成的），教训表或否决记录本身坏了才请你介入。
- **协议注册**：平时只在没注册或注册的脚本已不存在时补注册；install 时指向运行版。手动对副本表跑一次 check 不会再把负责人的按钮改指到副本。
- **记录与日志**：提醒记录 14 天后真正清掉；日志超过 1 MB 轮转、扫描结果没变就不重复写、弹窗正文的换行写成 ⏎。任何未捕获的异常都写进日志（pythonw 下没人看得到报错）。弹窗正文挤不下的消息不记已通知，下一轮再说。
- **互相看守**：看门狗自己停了没人报——每日学习跑完顺手看一眼看门狗的心跳，超过 12 小时没巡检就常驻弹一次（每天最多一次）。心跳只认计划任务那一轮（common.task_heartbeat，看门狗、status、doctor、处理页同一处）：每日学习跑完顺带的那轮、手动 `run check` 的那轮都不算，免得巡检任务停了还显示正常。状态文件里有字段类型坏了，巡检照常跑；入口真崩了常驻提醒一次（每天最多一次）。已安装时，正本改过还没部署也会写在处理页上（不弹窗）。
- **规范扫描**（handoff_flow.py v0.3）：W2 只写没回流——回流路径写成 US3 绝对路径的先映射回本机再核对，裸路径依次试 docs 根、工作区根、报告目录，frontmatter 用 YAML 解析；W3 碎片化按文件名里的写作时刻判窗口（不再按同步落盘的改动时刻）。新条目不弹窗，只进清单与处理页一行；扫描本身没跑成才请负责人介入；清单内容没变不重写。

## 八、安全边界

| 风险 | 现在怎么防 | 还剩什么 |
|---|---|---|
| 判决报告里埋指令，经模型变成规矩进每个会话 | 分隔符每轮随机且向模型说明、正文里与头部字段里的仿冒分隔行改写；越界词、注入形态、看不见的字符硬拦（原文与写进表的样子各查一遍、全角转半角后查，池里也重查，不能经池绕过；竖线写表时换全角竖线 ｜ 而不是全角斜杠——后者 NFKC 下就是 /，会把「C:|Users|…」造成路径；盘符、.env 紧贴汉字也认；裸域名、凭证、口令也拦）；池补入至少要一条引文对得上；生效版正文净化、@ 换全角；页首声明不授权执行 | 自由文本的语义无法程序化证明；靠逐条简述＋当场撤。为什么只对规矩正文设硬门、不对"为什么"设：后者不进生效版、显示时已转义，而叙述里常有"同步""删除"，设硬门会大量误拦 |
