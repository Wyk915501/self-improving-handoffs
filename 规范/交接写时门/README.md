# 交接写时门

**为什么存在**：写交接报告的格式规矩（[交接模板](../../工作传递/交接模板.md)、[工作传递总规则](../../工作传递/README.md)）早就写着，但同类错误照样反复出现——09-08 一天里另一窗口写的 8 件全是 `ready_for_review` 却 `frozen_at: none`，另一个项目 一件把状态行放在 frontmatter 之前导致整个 frontmatter 失效。**写在文档里的规矩没人在写的时候看。** 这个目录里的脚本让规矩在"写"的那一刻自动执行，让反复出现的错误自动变成下次要遵守的规矩，不靠人记、不靠人审。

**谁该看**：负责人（决定装不装、装在哪、怎么否决、怎么暂停）；Codex／US3 Claude（审脚本逻辑、部署 US3）；任何要在新机器上部署的人。

**什么时候看**：部署前；脚本报了你不理解的错时；想否决一条教训时；想加一条新检查项时。

## 一句话说清它是什么

**交接报告质检员 + 多 AI 共用错题本 + 错题本的生效版分发。** 不是任务总指挥：它不传文件、不派任务、不唤醒别的 AI，不验证研究结论和代码对不对；新增一条教训也**不会**自动变成新的程序检查项（教训表由 AI 读，机械检查由代码执行）。按 Codex 09-08 的分法，"接通了"（规则能到达使用端）、"运转了"（能持续运行处理异常）、"有用了"（真实任务质量／成本／人工负担改善）是三件事，下面分开标。

## 写后检查查什么（handoff_gate.py v2.5）

| 编号 | 查什么 | 为什么 |
|---|---|---|
| G1 | frontmatter 从第 1 行开始、200 行内闭合、是合法 YAML 映射、无重复键（含带引号的键）、无非法值（如坏日期）；本机没装 PyYAML 时 fail-closed | 状态行写在 `---` 前面 YAML 整个失效；重复键解析器只留一份 |
| G2 | `status` 只能是 `draft` 或 `ready_for_review`（带引号同样接受） | 报告文件自身不用 frozen／reviewed，处置写索引 |
| G3 | 模板顶层键齐全（读仓内 交接模板.md 的键清单；`full_contract_finalize` 仅 `multi-ai-loop/v1` 必填） | 缺键就无法按 ID 追溯 |
| G4 | `ready_for_review` 时 `frozen_at`、`observed_at` 必须是带时区偏移的时间；`frozen_at` 不得比现在晚 60 秒以上；`observed_at` ≤ `frozen_at` 且不在未来 | 冻结时刻写 none 等于没冻；写在未来叫预盖（09-08 作者自己就被拦过一次） |
| G5 | 正文不引用会话临时目录 | 复核方打不开。举证类引用同行加 `gate:allow-temp` 豁免 |
| G6 | 相对 markdown 链接都能在本机打开（支持 `<带空格目标>`、带标题、引用式定义；跳过围栏代码与行内代码；文件名含 `#` 的先整体查） | **只证明本机存在**；从 US3 拉下来的件链到本机尚未同步的文件时会报 G6，那是同步滞后。**扫描模式与待处理清单滤掉 G6**（跨机假断链） |
| G6P | **链接目标含反斜杠**，即使本机能打开也报（另一台机器必断，一律用正斜杠） | 单独编号是为了让扫描与清单只滤 G6 不滤它（v2.4 曾把两类都写成 G6，被扫描一起滤掉，GLM 二轮抓到） |
| G7 | 仅 hook 模式、提示性：本次写入的是 `frozen_at` 已过 30 分钟的 `ready_for_review` 件 | 冻结件不回改，要改写前向更正件。只按年龄判断，不证明冻结历史 |
| G0 | 报告**文件名**含反斜杠 | Windows 分隔符混进 Linux 文件名，文件躺在子任务根目录叫 `claude-code\2026-…`，既不在目录里也不在索引里（09-09 US3 两份实例） |
| G8 | **索引 README 的链接**（只对 `工作传递/**/README.md`，不套 G1–G7）：①解释 CommonMark 合法标点转义并去掉锚点后，文件路径仍含反斜杠；②目标是**同目录裸文件名**（不含 `/` 与 `..`、非绝对路径）但本机当前不存在（与目录清单逐字比对，**大小写不同也算不存在**，不靠 NTFS 的不区分大小写 `exists`）；③目标带**正斜杠目录前缀**、整体不存在（逐段精确比对，`Sub/` 与 `sub/` 不同）、但末段就在本目录（把自己所在目录又写了一遍，如 `claude-code/文件`）。`_archive/` 下的 README 整个跳过；文件名里的 `#` 不当锚点（先整体查，再按最后一个 `#` 剥）；目录列不出直接报 | 09-09 三份索引把链接写成 `claude-code\文件名`，README 自己就在 claude-code/ 里，解析后必断；"文件放错"（G0）与"索引行写错"（G8）是两个独立缺陷。G8 是保守检查，不承诺零误报：同目录文件可能仍在分批同步，须先确认同步完成；含 `../`、绝对路径、http、子目录的链接不报也不代表有效。v2.3 补上合法反斜杠转义与 `~~~` 围栏，避免把 Markdown 示例当真链接。首跑另抓到 GLM 索引 `OSP17`／`报劥告` 两处真笔误，交其来源 owner 修 |

报告检查（G0–G7）只对**路径含"工作传递"且文件名以"_交接报告.md"结尾**的文件生效；索引检查（G8）在 `--scan` 与显式指定 README 时查全部三类；**hook 写 `工作传递/**/README.md` 时当场只报①③两类确定性错误**（②"同目录目标不存在"留给扫描，因为索引常先于报告落盘，当场报会误拦）。hook 对 README 不套 G1–G7；载荷深搜跳过 `content`／`new_string` 等正文字段，索引正文里出现别份报告的绝对路径不会把检查对象劫持成那份报告。调度成功、README 仍在扫描窗口内且错误落在 G8 覆盖语法时，后续扫描可以发现；旧文件超窗、调度失败或排除语法不保证发现。链接解析覆盖常见写法，不是完整 Markdown 解析器：引用块内围栏、带转义括号的复杂目标仍可能误报，遇到先人工核对。hook 模式其余静默放行；CLI 模式任何显式指定却没查到的文件（缺失／范围外）都返回 2，扫描目录不存在也返回 2。**它是"写后提示"，不是闸门**：拦不住写入，也不覆盖 Bash／同步脚本／Codex 等其他写入来源。

## 怎么部署写后检查

**Windows 本机（已装）**：**2026-09-19 起装在项目级** `Desktop/Claude/.claude/settings.local.json`（与工作流写时门同处），同一段配置：

```json
"hooks": { "PostToolUse": [ { "matcher": "Write|Edit|MultiEdit", "hooks": [ {
  "type": "command",
  "command": "<HOME>/AppData/Local/Python/pythoncore-3.14-64/python.exe",
  "args": ["-X","utf8","<HOME>/Desktop/Claude/docs/规范/交接写时门/handoff_gate.py","--hook"],
  "timeout": 20, "statusMessage": "交接报告写时门" } ] } ] }
```

**为什么从用户级挪到项目级**：用户级 `settings.json` 会被 cc-switch 切模型时**整份替换**——GLM 档案里没有 hooks 键，一切 GLM 就把 hook 静默顶掉（09-18 实际发生过，09-19 查明并修复）。项目级配置 cc-switch 碰不到；检查对象（`docs/工作传递/`）本来只在这个项目里写，作用域无实际损失。同日把 cc-switch 官方档案里残留的 hooks 段删掉（防双触发）。验收记录：09-19 用全新嵌套会话写坏件，当场收到 G1 提示（[接线验证过程](../../工作传递/自我改进循环/claude-code/README.md)）。旧位置（用户级 A／B 两账号）随 B 线退役一并退场，细节见 [claude-use 文档](../../参考资料/claude-use-账号切换与US3部署.md)。

hooks 热重载，改完不用重启；`jq -e` 只证明 JSON 合法，**验收要靠一次"故意写坏件 → 收到提示"的真实 Write／Edit**。

**ZCode（本机 GLM 客户端，已装）**：ZCode 支持同一套钩子事件（`SessionStart / UserPromptSubmit / PreToolUse / PermissionRequest / PostToolUse / PostToolUseFailure / Stop`，也支持 `type: "command"`），但配置形状不同：多一层 `events`，且 `command` 是**单个字符串**（没有 `args` 数组）。配置在项目级 `.zcode/config.json`：

```json
{ "hooks": { "enabled": true, "events": { "PostToolUse": [ { "hooks": [ {
  "type": "command",
  "command": "\"…/python.exe\" -X utf8 \"…/handoff_gate.py\" --hook-strict --root \"…/docs/工作传递\"",
  "timeoutMs": 20000, "statusMessage": "交接报告写后检查" } ] } ] } } }
```

三点说明：①用 `--hook-strict`（原因写 stderr、退出码 2），因为不确定 ZCode 认不认 Claude Code 那套 JSON 决策；②**不写 `matcher`**，因为 ZCode 的工具名未必叫 `Write`／`Edit`，靠脚本自己筛路径更稳；③给了 `--root`，脚本在载荷里找不到报告路径时会兜底扫最近 15 分钟改动的报告（限流 60 秒一次、同一文件同一改动时刻只报一次、一次最多 3 件）。**未做**：没在 ZCode 里真开会话验证过，只用 `shell=True` 模拟钩子运行器跑通了命令行。

**US3（待负责人点头，由 Codex 执行）**：装在 **`<项目根>/.claude/settings.json`（项目级，新建）**，不碰 `/root/.claude/settings.json`（全团队共用 root），不动已有的 `settings.local.json`。配置样稿：[us3-project-hook.review.json](../../工作传递/自我改进循环/codex/2026-09-08_交接写时门复核/us3-project-hook.review.json)（`/usr/bin/python3` + 脚本绝对路径 + `--hook`）。项目级配置只在**会话从 `<项目根>` 根启动**时加载。验收＝在 `<项目根>` 下开一个 Claude 会话，故意写一份坏交接报告，收到提示。

## 每日学习（handoff_lessons.py v3.6，HandoffDaily 09:00）

回答的问题：**Codex／US3 Claude 每天判出来的机制类问题，怎么不经人手变成下次写件要遵守的规矩。** 一个入口 `daily`，加锁串行三步，**模型全程无文件写权**：

1. `collect`：程序按上次扫描位置 + 积压队列枚举 codex／US3／GLM 来源的新判决件，把正文当**不可信引文**送给 `claude -p`（sonnet，`--tools ""` 无工具，`--json-schema` 只收 JSON）；模型只返回候选。**程序**验证：每条证据的引文必须**逐字见于该判决件原文**；≥2 条证据来自不同判决件且指向 ≥2 个**不同原始事件**（`feedback_for`，缺则 `related_reports` 首项，再缺不计；**指向的原件必须在树内实存**，编造的 ID 不算）；类别在九类白名单（09-20 v3.6 补「正本与索引维护」「验收与状态」两类——病根①：这两类本是协作教训主场，缺类目导致好候选全灭）；与现有行、已否决行、本批已接受候选都不近似；命中越界关键词（权限／部署／同步／冻结机制／检查器／git／发布／删除／移出／改名／密钥…）的不进表——**这只是自由文本之上的额外一层，换个说法就绕得过；反过来它也会误拒合法教训**（词表里曾有"目录／检查／扫描／待处理"四个宽词，把"索引与文件同目录时只写裸文件名"这种正该学的拦进观察，二轮已删；观察记录里的拒收不都是该拒的），真正的守门是逐字引文＋独立事件＋48 小时否决窗；日增 ≤2（从表本身数）、生效+拟生效 ≤15（超了 publish 只打警告，不截断）。已处理的件按 `report_id@改动时刻` 记，改过内容的件会再读一次（09-09 首跑留下的裸 `report_id` 条目不再被认，否则那 26 件改了也永久跳过；它们早于扫描位置，不会因此重扫）。通过的由程序分配编号、按真实加入时刻 +48 小时写到期、追加行。
2. `promote`：否决记录里点名的行——**不论拟生效还是已生效**——同步为"否决（见否决记录）"；到期且带"加入"标记、到期−加入 ≥ 48 小时的拟生效行转生效；写前重读比对、原子替换。每天跑一次，所以实际生效在 48–72 小时之间。
3. `publish`：生成 [协作教训-生效.md](../../工作传递/协作教训-生效.md)。

**程序守不住的两条**：①候选规矩是自由文本，程序无法证明它只关于"报告写法与协作"；②判决件的叙述本身不可验证——"原件实存"只验存在不验相关，一份判决件填任意真实 `report_id` 再虚构一段教训、引文取自自己正文，四道兜全过（原件须在来源目录之外，判决件互引已不算，三轮窄版）。这一层的实际效果是"编造的 ID 过不去"，不是"编造的事过不去"。负责人 09-08 已接受该残余风险（两处逐字引文 + 不同原始事件 + 48 小时否决窗 + 否决记录 + 常驻弹窗）。

**被拒候选池（v3.6，09-20 病根②）**：被拒 ≠ 死路。collect 里除垃圾（字段缺失）与重复（与现有行／已否决／本批已接受近似）外的**所有**被拒候选——超字数、类别不合（含「其他」）、越界关键词、证据不足、冲突、配额——写入本机 `~/.claude/tools/handoff_rejected_pool.json`（上限 20 条待裁量，池内按 similar 去重）。看门狗处理页新增「被拒的好点子」区：每条给全文＋程序当时的拒因＋「采纳／不用」按钮（`handoff-rule:adopt|drop/RP-xxx`）；**采纳＝写成人工行进表**（拟生效 48h、出处注明原拒因，人工行不受 60 字自动上限约束，同 LG-06/07 先例），不用＝翻篇。池子本身不触发弹窗（弹窗契约不变），只在页面上出现。09-20 已把状态文件里攒的 17 条历史观察一次性回填进池。越界关键词词表**有意不动**：它拦的"直接覆盖即可"类危险货必须继续拦在自动生效之外——误伤的好规矩走池子由人裁量，两类矛盾同时解决。

**尚未实现**（Codex 2230 §三.4）：规则的修订／替换／停用链路——现在只会追加和否决；满 15 条后新想法只进观察。

## 负责人怎么用（自然语言版）

- **平时**：什么都不用做。写报告的 AI 会收到提示自己改；教训表自己长；生效版自己更新。
- **拍板一条新规矩**：弹窗点「去看看」→ 处理状态页顶部「等你拍板」区，每条给**全文＋为什么会有这条＋谁提的＋什么时候生效**，下面两个按钮：**「同意，就这么定」**（记一笔，以后不再拿这条提醒你）／**「不采纳」**（写进否决记录，它就不会生效）。
  也可以手动在 [否决记录](../../工作传递/协作教训-否决记录.md) 加一行"编号｜日期｜谁"。已生效的也能撤回。
  **反悔**：删掉否决记录里那一行即可，下次运行就当没否决过。
  ⚠ "脚本永不写否决记录"这句从 09-10 起要说准确：**自动流程（collect／promote／publish／看门狗轮询）仍然一行都不碰它**；只有你点按钮时才由 `handoff_notify.py rule no/<编号>` 追加一行，且只追加、不改已有行、重复点不重复写、编号必须在表里真实存在、非 `ok|no` + `LG-数字` 一律忽略（协议注册给全系统，得防别人乱调）。
- **暂停自动学习**：PowerShell 里 `Disable-ScheduledTask -TaskName HandoffDaily`（恢复 `Enable-ScheduledTask`）；写后检查与弹窗独立于它。
- **恢复某个版本**：脚本、表、生效版都在 docs 树里，本机与 US3 各一份；表每次改动有更新记录一行，脚本改版记在本 README。
- **弹窗与处理页的分工（09-10 按负责人反馈重定）**：**弹窗不是做决定的地方**。一条规矩要不要，得读全文、读它是因为什么事才提出来的——这些塞不进一个弹窗，塞了也只会让人不知所措。所以：
  - **弹窗只负责叫你去看**：一句话说清有这么回事、不管会怎样，一个按钮「去看看」。**弹窗里不出现内部编号（LG-06 这种）、不出现"否决/拟生效/每日学习"这类内部词、也不摆规矩正文**——测试里有断言盯着，别写回去。
  - **判断在处理状态页上做**：顶部「等你拍板」区，每条规矩全文、为什么会有这条、谁提的、什么时候生效，两个按钮当场定。
  这条是负责人 09-10 看到实弹弹窗后连提三次定下来的："我压根不知道 LG-06 是什么"、"要么就是跳转出去让我去看实际内容然后再给我的意见"。
- **"到点"不等于"已生效"**：48 小时窗到点只是到点，真正翻牌要等下一次每日学习（每天北京 09:00），中间这段最长十几小时里拍板仍然有效——弹窗在这段里会继续提醒。
- **不再闪终端窗口（09-10）**：两条计划任务原本用 `python.exe`（控制台程序），每轮都会在屏幕上闪一下；现在改用 `pythonw.exe`，脚本相应容忍 `sys.stdout is None`；toast／schtasks／publish／claude CLI 全部子进程加 `CREATE_NO_WINDOW`。**以后改计划任务别改回 `python.exe`。**
- **"有事会不会找我"**：在这台电脑前会——右下角常驻弹窗（新教训待否决／脚本自动处理了什么／报告没过检查／每日学习太久没成功跑），不点「知道了」不消失。人不在电脑前、电脑关机，看不到；离机告警要另选渠道。弹出也不证明你看过。**新教训到期前 6 小时**若你还没否决，会再升一次为常驻提醒（每条只升一次；看门狗在跑才有，见下一条盲区）。**升级窗 09-10 从 6 小时改成 12 小时**：看门狗 4 小时一轮，6 小时窗最坏只提前几十分钟——09-10 实况就是 16:00 才提醒 16:35 到期——错过这一次它就自动生效了，但已生效的照样能否决；**已经把这条读进上下文的进行中会话不会回收**，只有新会话读新生效版。
- **一个盲区要知道**：弹窗和状态页是看门狗程序自己发的。它报"通知发不出"时，你其实收不到这条；它自己没跑（计划任务被禁、电脑没开机），也没人替它报。判断方法只有一个：`~/.claude/tools/logs/handoff_notify.log` 最后一行的时刻超过 4 小时没更新，就是看门狗自己停了。
- **看到"某报告没过写后检查"该怎么办：什么都不用做。** 它的意思是那份报告的表头格式不对（程序读不出编号／时间／状态，追溯会断），内容本身不一定有错；该改的是**写它的那个 AI**。所以这类条目**不弹给你**，而是写进 [写后检查-待处理.md](../../工作传递/写后检查-待处理.md)（按"子任务/来源目录"分组、随 docs 同步；生效版页首有指向，各 AI 开工先自查）。只有同一个窗口一轮 ≥3 份新不合格才弹一条给你——那说明它没在看提示，值得你去说一句。
- **弹窗分两档，一眼分清要不要你**（负责人 09-09："我要的是一个自动的东西，只有它出了问题才需要我介入"）：

- **只有一个跳转按钮「看处理」**（负责人 09-09 指出多个按钮开同一页没意义）：打开短页 `<HOME>\.claude\tools\logs\handoff_status.html`——第一节"需要你介入：N 项"，每项一句该做什么＋一个可点的去处（去否决记录／打开待处理清单／看日志）；第二节"系统自己在做的"；第三节"细节入口"（逐份报告问题清单 `handoff_findings.html`、待处理清单、完整教训表、否决记录、日志、暂停命令）。两页都每次运行重写。按钮走 Windows 协议激活；万一被系统拦住，日志里每次都写状态页的完整路径，手动打开即可。
- **定时任务**（当前用户、仅登录时运行；⚠ 在 Git Bash 里敲 `schtasks /TN` 会被 MSYS 转成路径而失败，要改就在 PowerShell 里改）：HandoffDaily 北京 09:00（**09-10 起带 `--provider glm`，不再传 `--config-dir`；要换回 Claude 账号就把这两个参数换回来**）（**触发器写的是本机时钟 21:00**——本机系统时区是 UTC−4，比北京慢 12 小时；09-09 首版误写成本机 09:00＝北京 21:00，已改）（`handoff_lessons.py daily … --config-dir <账号目录>`）、HandoffNotify 每 4 小时（`handoff_notify.py check …`）。`collect` 调 `claude -p` 用 `--config-dir` 显式指定已登录账号，不依赖环境变量；`--json-schema` 的结构化输出靠一次工具调用交付，所以 `--max-turns` 必须 ≥2（首跑用 1 撞过，退出码 1）。**烧谁的额度（09-10 负责人问后做成开关）**：整套只有"每日学习"的提名那一步调模型，一天最多一次；写后检查、看门狗、US3 那条 cron **零模型调用**。提供方用 `--provider` 选：
  - `glm`（**本机现行**）：走智谱 `GLM_API_KEY`，默认 `glm-5.3`，端点自动在订阅制／充值两个里试，**Claude 账号一个 token 都不动**。09-10 实跑：23 件、12 万字符 → 输入 67902、输出 21611（思考 20560），端点 `coding/paas/v4`。

  ⚠ `GLM_API_KEY` 是**用户级环境变量**：已经启动的进程读不到新设的值；计划任务起的新进程读得到（09-10 用一次性探针任务实测过）。
