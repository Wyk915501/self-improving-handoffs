# 交接写时门 · 回归测试

**为什么存在**：Codex 的 [reproduce.py](../../../工作传递/自我改进循环/codex/2026-09-08_交接写时门复核/reproduce.py)、[check_*_v2.py](../../../工作传递/自我改进循环/codex/2026-09-08_v2合并复核/README.md)、[check_boundaries.py](../../../工作传递/自我改进循环/codex/2026-09-08_规则连接复核/README.md) 是"缺陷复现"脚本，锁定被审版本的 SHA，脚本一改就拒跑；它们是历史证据，不是正确性测试。这个目录放**正确行为**的回归测试，脚本每改一版都要跑一遍。

**谁该看**：改 handoff_gate.py／handoff_lessons.py／handoff_notify.py 的人；复核的人（Codex／US3）。

**什么时候看**：改脚本之后、交出之前。

## 怎么跑

```
py -X utf8 docs/规范/交接写时门/handoffctl.py test          # 六套一起跑，打印被测文件 SHA（推荐）
py -X utf8 -B docs/规范/交接写时门/tests/test_gate.py       # 写后检查 70 项
py -X utf8 -B docs/规范/交接写时门/tests/test_lessons.py    # 每日学习 144 项（假模型、假 claude 子进程，不联网）
py -X utf8 -B docs/规范/交接写时门/tests/test_notify.py     # 看门狗 120 项（不弹窗、不碰注册表、不读真机计划任务）
py -X utf8 -B docs/规范/交接写时门/tests/test_ui.py         # 弹窗与处理页 128 项（ps1 演练只在 Windows 真跑，别处记 SKIP）
py -X utf8 -B docs/规范/交接写时门/tests/test_flow.py       # 规范扫描 25 项
py -X utf8 -B docs/规范/交接写时门/tests/test_ctl.py        # 统一入口 43 项（临时运行目录，不碰真实安装）
```

US3 上把 `py -X utf8` 换成 `python3 -X utf8`。`handoffctl.py promote` 会先跑这六套，全过才部署运行版。SKIP 不是 PASS：test_ui 在非 Windows 上跳过的 ps1 演练，要回 Windows 跑过才算验过。

**隔离承诺**：每套开头先清掉继承来的 `HANDOFF_*`／`HN_*`／`HL_*` 环境变量（第十批打包时发现：外面设了 `HANDOFF_HOME`，它会压过测试自己的临时目录，候选池、页面、日志就写进真目录了）；状态、日志、页面全走临时目录（`HANDOFF_TOOLS_DIR` 或 `HANDOFF_HOME`）；看门狗与弹窗那两份设 `HANDOFF_NO_REGISTER=1`，不写协议与通知署名两处注册表，弹窗桩在传输层（`_send`），文案净化与分类照常经过；统一入口那份用临时 `HANDOFF_HOME` 与临时项目目录，不碰真实计划任务、钩子配置。测试与它们起的子进程都不写 `__pycache__`（正本目录在 docs 同步域里）。夹具日期一律相对"今天"生成。
