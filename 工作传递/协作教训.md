# 协作教训（样例表）

**这份回答什么**：多 AI 写交接报告、改正本时，哪些错反复犯过、以后怎么防。整棵 docs 树共用一份。

**本包里这份是合成样例**：格式与脚本要求的一致（编号／状态／规矩／为什么／出处五列；状态只认「生效…」「否决…」与遗留的标准「拟生效（至 YYYY-MM-DD HH:MM）」；自动加入的行出处格带「加入 时刻（自动）」），内容是把原项目里几条通用规矩改写后放进来，"为什么"与"出处"不是真事。装到你那里请清空表体，从 LG-01 开始让每日学习自己加。

## 教训表

| 编号 | 状态 | 一句话规矩 | 为什么（真实发生过的事） | 出处 |
|---|---|---|---|---|
| LG-01 | 生效 | 写共享正本前记下它的 sha256 并重读；哈希变了就放弃旧补丁重新合成，不抢写 | 两个窗口同时改同一份正本，整文件被覆写 | 审查回执甲／乙（样例） |
| LG-02 | 生效 | 时间戳一律从带时区的时钟换算，别读本机本地时钟；冻结件不回改，纠错前向追加 | 文件名时间比实际晚、frozen_at 写成计划时间 | 审查回执丙／自查丁（样例） |
| LG-03 | 生效（2026-10-01 自动） | 写"已实测"时出处必须是复核方打得开的位置；会话临时目录不算出处 | 两份报告引用了只在本机存在的临时目录 | 回执戊／己（样例）；加入 2026-10-01 09:00（自动） |

## 怎么运转

每天一次：`handoff_lessons.py daily`（或 `handoffctl.py run daily`）依次收信号（模型提名、程序核验，通过的当天写成生效行）、否决同步（不采纳记录里点名的行改状态）、池补入、发布（生成同目录的生效版）。不采纳写同目录的 协作教训-否决记录.md 的表格，或在处理页点「不采纳」。
